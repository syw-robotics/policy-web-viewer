# MuJoCo UI Rendering Parameters

This document describes the key parameters that affect the MuJoCo/Three.js rendering and interaction experience in `policy-web-viewer`. UI changes should start in `frontend/`. Do not hand-edit `src/policy_web_viewer/static/`; it is generated by `npm run build:api`.

## Frontend Source

Local development and static export share the same frontend source:

```text
frontend/
  index.html
  src/render_config.js
  src/styles.css
  src/runtimes/api_runtime.js
  src/runtimes/wasm_runtime.js
```

- `render_config.js`: shared rendering and interaction parameters. Home view, camera, lighting, shadows, floor, materials, contacts, force, and torque should be changed here first.
- `api_runtime.js`: local `policy-web-viewer` page backed by the Python `/api`.
- `wasm_runtime.js`: exported static page backed by browser MuJoCo WASM.
- Both runtimes import `render_config.js`. Avoid duplicating shared rendering constants in runtime files.

## Camera And Home View

Camera projection:

```js
CAMERA_CONFIG = {
  fov: 45,
  near: 0.01,
  far: 100,
}
```

- `fov`: vertical field of view. Larger values create stronger perspective.
- `near`: near clipping plane. If too large, close geometry is clipped.
- `far`: far clipping plane. If too small, distant floor or robot geometry is clipped.

Current Home view:

```js
target: [0, 0.85, 0]
position: [-4.0, 1.5, 2.0]
```

- `target`: the point the camera orbits around, usually near the torso height.
- `position`: the camera world position for Home.
- Pressing `Home` resets the orbit target, radius, theta, and phi from these values.

To change the initial view and Home view, edit `HOME_VIEW` in `frontend/src/render_config.js`.

## Orbit Interaction

Important orbit controls:

- Left-drag empty space: rotate.
- Middle- or right-drag empty space: pan.
- Wheel: zoom.
- Radius limits: `0.8` to `14`.
- Rotate speed: `0.0045`.
- Pan speed: `radius * 0.0012`.
- Vertical angle limit: `0.18` to `Math.PI - 0.18`.

These values determine how responsive the camera feels, whether it clips through the model, and how easily users can lose sight of the robot.

## Background, Fog, And Color

Current scene tone:

```js
SCENE_CONFIG = {
  background: 0x2d3b3d,
  fogNear: 9,
  fogFar: 18,
}
```

- `background`: background and fog color.
- `fogNear`: distance where fog starts.
- `fogFar`: distance where fog becomes prominent.

If the image is too dark, tune lighting first. If distant floor detail is distracting, tune fog.

## Lighting

The scene uses three light types:

```js
LIGHT_CONFIG = {
  hemisphereSky: 0xcfe7ff,
  hemisphereGround: 0x26322d,
  hemisphereIntensity: 1.1,
  keyColor: 0xffffff,
  keyIntensity: 2.2,
  rimColor: 0xa8c8ff,
  rimIntensity: 0.65,
}
```

- Hemisphere light: ambient fill, controls dark-side visibility.
- Key directional light: main light, primary shading and shadow source.
- Rim directional light: side/back fill, helps silhouettes remain visible.

The key light position is:

```js
keyLight.position = target + [4.5, 7.5, 4.0]
```

The `target` follows the robot, so shadows should remain available as the robot moves.

## Shadows

Shadow settings live in `SHADOW_CONFIG`:

```js
SHADOW_CONFIG = {
  mapSize: 2048,
  near: 0.2,
  far: 18,
  left: -7,
  right: 7,
  top: 7,
  bottom: -7,
}
```

- `mapSize`: shadow map resolution. Higher is sharper but more expensive.
- `near/far`: shadow camera depth range.
- `left/right/top/bottom`: shadow coverage area.
- If shadows disappear after the robot moves far from the origin, check whether the key light follows the robot and whether the shadow camera coverage is large enough.

## Floor

Current floor settings:

```js
FLOOR_CONFIG = {
  size: 120,
  repeat: [18, 18],
}
```

- `size`: visual floor size, not necessarily the MuJoCo physical floor size.
- `repeat`: grid texture repeat count.
- `roughness: 0.86` keeps the floor mostly matte.

## Materials

Default geometry material:

```js
GEOM_MATERIAL_CONFIG = {
  roughness: 0.52,
  metalness: 0.03,
  clearcoat: 0.15,
}
```

- `roughness`: higher means more matte.
- `metalness`: keep low if the robot should not look metallic.
- `clearcoat`: light highlight layer; too high can look plastic.

## Resolution And Performance

Pixel ratio cap:

```js
SCENE_CONFIG.maxPixelRatio = 2
```

- Caps DPR at `2` to control GPU cost on high-DPI screens.
- If the page stutters, try `1.5` or `1`.

Local API frame polling:

```js
await sleep(33)
```

This is about 30 FPS for state updates. Three.js rendering still uses `renderer.setAnimationLoop`.

WASM simulation timing comes from the exported manifest:

- `sim_hz`
- `physics_dt`
- `policy_step_dt`
- `decimation`

These affect browser simulation speed and policy update cadence.

## Contacts Visualization

The Contacts button shows contact points and force arrows:

```js
CONTACT_CONFIG = {
  forceScale: 0.006,
  forceMaxLength: 0.8,
}
```

- `forceScale`: contact force to arrow length scale.
- `forceMaxLength`: maximum arrow length.
- Contact points are small blue spheres; contact forces are blue arrows.

## External Force And Torque

Force drag:

```js
FORCE_CONFIG = {
  dragGain: 30.0,
  dragMax: 80.0,
  arrowMaxLength: 1.25,
}
```

- `dragGain`: mouse drag offset to external force gain.
- `dragMax`: maximum force.
- `arrowMaxLength`: maximum force arrow length.

Torque drag:

```js
TORQUE_CONFIG = {
  dragDeadzonePx: 10.0,
  dragGain: 0.15,
  dragMax: 20.0,
}
```

- Right-drag the robot to apply torque.
- `dragDeadzonePx` prevents accidental tiny movements.
- `dragGain` and `dragMax` determine torque strength.

## UI Controls

Main buttons:

- `Run/Pause`: start or pause simulation.
- `Reset`: reset simulation.
- `Follow`: whether the camera target follows the robot.
- `Contacts`: show contact points and force arrows.
- `Home`: reset view.
- `Force`: enable mouse force and torque drag.

Button layout, panel colors, typography, and spacing live in `frontend/src/styles.css`.

## Sync Workflow

Local debugging:

```bash
policy-web-viewer \
  --robot g1 \
  --ckpt /home/syw/.gitrepos/unitree-deploy/ckpt/g1/vanilla_ppo_flat
```

Build local static assets:

```bash
npm run build:api
```

Export a GitHub Pages-ready directory:

```bash
policy-web-viewer-export \
  --robot g1 \
  --ckpt /home/syw/.gitrepos/unitree-deploy/ckpt/g1/vanilla_ppo_flat \
  --out export/g1-demo \
  --overwrite
```

Rules:

- Shared HTML/CSS changes should go to `frontend/index.html` and `frontend/src/styles.css`.
- Rendering parameters should go to `frontend/src/render_config.js` so local and exported pages change together.
- Environment-specific logic belongs in `api_runtime.js` or `wasm_runtime.js`.
- Do not hand-edit `src/policy_web_viewer/static/`.
